TerraformのSentinelポリシー管理

ポリシーチェックの役割Sentinel CLIとファイルの準備ポリシーの作成正常・違反ケースのテストHCP Terraformへの適用追加するルールの選び方

SentinelでPlanの設定値を検査し、正常・違反ケースをテストしてHCP Terraformへ適用する手順

ポリシーチェックの役割

SentinelはTerraformのPlanなどを検査し、組織のルールに合う変更かを判定する仕組み。Terraformの構文検証やIAM権限とは別の役割

検査目的
terraform validateTerraform構成の構文・整合性を検査
terraform plan追加・変更・削除・置換を確認
Sentinel許可した設定、タグ、利用可能な機能などを判定
IAMAWS APIに対する実際の操作権限を制御

この例では検証用SQSの最大メッセージサイズを2048または4096バイトに限定。AWSの上限ではなく、この手順の練習用ルール。適用先は検証用Workspaceだけに限定

Sentinel CLIとファイルの準備

Sentinel CLIを公式配布からOS・CPUに合う形式で導入し、PATHを設定。Terraform CLIに内蔵されているコマンドではない。HCP Terraformでのポリシー利用可否・管理権限も対象Organizationで確認

① VS Codeの統合ターミナルでSentinel CLIを確認

PowerShell
sentinel version

② Terraform構成とは別のポリシー用フォルダーを作成。既存フォルダーの場合は別名を使用

PowerShell
New-Item -ItemType Directory -Path "$env:USERPROFILE\IaC\Sentinel\sqs-policy"
Set-Location "$env:USERPROFILE\IaC\Sentinel\sqs-policy"
New-Item -ItemType Directory -Path "test\queue-size"
配置例
sqs-policy/
  queue-size.sentinel
  sentinel.hcl
  test/
    queue-size/
      pass.hcl
      fail.hcl

ポリシーの作成

① queue-size.sentinelを保存。削除だけの変更を除き、SQSの適用後の値を確認。値が計画時点で不明な場合も許可せず、検証対象として扱う

queue-size.sentinel
import "tfplan/v2" as tfplan

queues = filter tfplan.resource_changes as _, resource {
  resource.mode is "managed" and
  resource.type is "aws_sqs_queue" and
  resource.change.actions is not ["delete"]
}

main = rule {
  all queues as _, resource {
    (resource.change.after.max_message_size else 0) in [2048, 4096]
  }
}
記述役割
import "tfplan/v2"HCP Terraformが渡すPlanデータを参照
filter管理リソース・SQS・削除のみ以外に対象を絞る
rule真偽値を返す検査ルール
all対象の全要素が条件を満たすかを確認
else 0未定義の属性を0として扱い、許可値には一致させない
mainポリシー全体の判定結果

対象SQSが0件ならallはtrue。キューが必ず存在することも強制したい場合は、length(queues)の条件を追加。置換のactionsはdeleteだけのリストではないため、置換後の値も検査

② sentinel.hclを保存。最初は検証用のadvisoryでRunへの影響を確認

sentinel.hcl
policy "queue-size" {
  source            = "./queue-size.sentinel"
  enforcement_level = "advisory"
}

正常・違反ケースのテスト

① 許可する値を持つモックと、期待結果trueを設定

test/queue-size/pass.hcl
mock "tfplan/v2" {
  data = {
    resource_changes = {
      "aws_sqs_queue.practice" = {
        mode = "managed"
        type = "aws_sqs_queue"
        change = {
          actions = ["create"]
          after = {
            max_message_size = 2048
          }
        }
      }
    }
  }
}

test {
  rules = {
    main = true
  }
}

② 許可しない値を持つモックと、期待結果falseを設定

test/queue-size/fail.hcl
mock "tfplan/v2" {
  data = {
    resource_changes = {
      "aws_sqs_queue.practice" = {
        mode = "managed"
        type = "aws_sqs_queue"
        change = {
          actions = ["create"]
          after = {
            max_message_size = 8192
          }
        }
      }
    }
  }
}

test {
  rules = {
    main = false
  }
}

③ ポリシーフォルダーでテストを実行。両ケースがPASSとなることを確認

PowerShell
sentinel test -verbose queue-size.sentinel

fail.hclもPASSが正しい結果。「ルールがfalseを返す」という期待に一致したことを示し、違反設定が許可された意味ではない

④ 適用前に、4096、許可外の値、属性未定義、削除のみ、置換、対象0件、複数キューのうち1件が違反するケースも追加。手書きモックだけでなく、検証用Runから得たモックでも確認

⚠️ 注意

ローカルSentinelにはHCP TerraformのPlanが自動で渡らない。tfplan/v2を使うテストにはモックが必要。Runから取得したモックにも秘密値が含まれ得るため公開前に確認

HCP Terraformへの適用

① ポリシー・sentinel.hcl・テストを専用VCSリポジトリへ保存。検証用モック以外のPlan・State・認証情報を含めないことを確認

② HCP TerraformのOrganization設定からPolicy Setsを開き、Connect a new policy setボタンを押下

③ VCSと対象リポジトリを選択し、Policy FrameworkはSentinelを選択。sentinel.hclがルート以外にある場合はPolicies pathに格納フォルダーを設定

④ 適用範囲を検証用Workspaceに限定して保存。参照するブランチ・ポリシーのパス・コミット・Enforcement levelを確認

⑤ 対象Workspaceで許可値のPlanと違反値のPlanを実行し、Policy Checkの判定を確認。違反ケースはApplyせず終了

⑥ 検証結果を確認してから必要な強制度へ変更。ポリシーを強制する場合は、違反Runが実際にApplyへ進めないことまで確認

Enforcement level違反時の扱い
advisory通知・確認用。違反してもApplyを阻止しない
soft-mandatory通常は停止。権限を持つ利用者によるoverrideが可能
hard-mandatory違反したRunをoverrideして続行できない

全Workspaceへの一括適用は検証後に判断。利用可能な管理方法はOrganizationの契約・設定で確認し、画面が利用できない場合にプラン変更を自動実施しない

追加するルールの選び方

入力検査例
tfplan/v2作成後のリソース属性、公開設定、サイズ、タグ
tfconfig/v2Providerやprovisionerの使用状況
tfstate/v2Stateに記録されたリソースの情報
tfrunRunやWorkspaceに関する情報

ルールは必須タグ、公開範囲、許可リージョン、provisioner制限などから小さく導入。共通処理はSentinelのモジュールへ分離し、取得元バージョンを固定

Terraformバージョンを制約する場合は文字列の大小比較ではなく、セマンティックバージョンとして比較。通常の実行バージョン制約はrequired_versionでも管理

誤検知した場合はモックに失敗ケースを追加し、ルールを修正して再テスト。ポリシー無効化や強制適用でその場だけ回避しない
