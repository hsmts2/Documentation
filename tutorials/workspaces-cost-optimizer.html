仕様

構成・動作

Cost Optimizer for Amazon WorkSpacesは、WorkSpaces本体の組み込み機能ではなく、AWS Solutions Libraryから提供されるCloudFormationテンプレートで構築するソリューションです。WorkSpacesの利用時間と料金しきい値を比較し、時間課金のAUTO_STOPと月額課金のALWAYS_ONのどちらが適しているかを日次で判定します。

図中の番号は、1：日次タスク起動、2：同一アカウントの利用状況取得と課金モード判定、3：DynamoDBの利用状況・セッション情報の保存と参照、4：S3へのCSVレポート出力を示します。東京リージョンにソリューションを配置し、監視対象リージョンはRegionsの設定に従います。

構成図の編集用PowerPoint

今回の構成では、東京リージョンにハブテンプレートだけをデプロイし、同一AWSアカウント内のWorkSpacesを監視します。スポークアカウントは使用しません。

構成要素 役割
Amazon EventBridge 1日1回、ECSタスクを起動する
Amazon ECS／AWS Fargate WorkSpacesの利用時間集計、料金しきい値との比較、課金モード変更を実行する
Amazon DynamoDB WorkSpaceの利用状況とセッション情報を保持する
Amazon S3 日次・月次CSVレポートとS3アクセスログを保存する
CloudWatch Logs／ダッシュボード 実行ログ、対象台数、変換件数、エラーおよび処理時間を確認する

EventBridgeが日次で起動するECSタスクは、WorkSpacesの利用状況取得、料金しきい値との比較、DynamoDBの状態参照・保存、S3へのCSV出力を行います。実行ログと運用メトリクスはCloudWatchへ出力します。

項目 今回の設定 事前に理解しておく内容
Dry Run 初期構築時はYes 判定結果をレポートへ出力しますが、課金モードは変更しない
未使用WorkSpace終了 No 未使用WorkSpaceを自動終了しない
除外タグ Skip_Convert 指定したWorkSpaceを課金モード変更と終了の対象外にする
監視対象リージョン Regionsは空欄 同一アカウント内の対応リージョンを走査するため、必要に応じて対象を限定する
VPC CreateNewVPC=Yes NAT GatewayとElastic IPが作成され、継続料金が発生する

⚠️ 注意：日次処理を重複実行しない
本ソリューションは1日1回の利用時間計算を前提としています。EventBridgeスケジュールの直接変更や同一UTC日内のECSタスク複数実行は、請求対象時間と課金モード判定を不正確にする可能性があります。CloudFormationを構成管理の正とし、配下のリソースを個別編集しません。

CloudFormationスタックを削除しても、S3バケット、DynamoDBテーブル、ECS実行ログおよびVPC Flow Logsの一部はDeletionPolicy: Retainにより残ります。削除時はデータ保持と残存料金を個別に確認します。

バージョン差分と作成リソースの詳細は、v2.8.1とv2.9.10の差分および作成リソース一覧を参照します。

Regions を空欄にすると、アカウント内の対応リージョンをすべて走査します。組織で未有効化のリージョンに対するエラーを抑え、処理範囲を明確にする場合は、WorkSpacesを運用するリージョンだけをカンマ区切りで指定します。

  3. ロールバック中に新規作成されたリソースは、通常の削除ポリシーに従う設定を維持します。
  4. AWS::IAM::Role 等の作成を確認し、「AWS CloudFormationによってIAMリソースがカスタム名で作成される場合があることを承認します」を選択します。
  5. 「次へ」を選択します。

6. デプロイ結果を確認する

  1. スタックが CREATE_COMPLETE となっていることを確認します。
  2. 「リソース」タブで、本構成では41件が CREATE_COMPLETE となっていることを確認します。
  3. 「出力」タブで SolutionVersion=v2.9.10、DryRun=Yes、BucketName、StandardLimit=85などの料金しきい値を確認します。

7. 作成後の注意

  • CreateNewVPC=Yes ではNAT GatewayとElastic IPが作成され、継続料金が発生します。
  • スタック削除後も、削除ポリシー Retain のS3、DynamoDB、CloudWatch Logsが残ります。
  • DryRun解除はデプロイ直後に実施せず、レポートを十分な期間確認してから行います。
  • 詳細は作成リソース一覧を参照します。

運用設定の管理

  • 料金しきい値とDryRunはCloudFormation変更セットで変更します。
  • CloudFormation配下のECSタスク定義、IAM、S3、EventBridge等を個別編集しません。
  • DryRun=No へ変更する前に、複数月分のDryRunレポート、お客様承認、除外対象、切り戻し方法を確認します。
  • 自動変更から除外するWorkSpaceには、公式仕様に従って Skip_Convert タグを使用します。
  • 成功可否はダッシュボードだけで判断せず、ECS、CloudWatch Logs、S3 CSV、WorkSpaces実設定を突合します。

概要 仕様 前提条件 運用作業 変更後確認

概要

項目 内容
目的 CloudFormationスタックsample-cfn-co-001の変更セットを使用し、DryRunをYesからNoへ変更します。変更対象と置換有無を確認して実行した後、CloudFormation、ECS、CloudWatch Logs、S3 CSVおよびWorkSpaces実行モードの順に確認し、設定更新と日次処理の成功可否を判定します。取得済み証跡ではCloudFormation更新まで完了しており、Dry Run解除後の初回日次処理と課金モード変更結果は未確認です。

仕様

構成・動作

⚠️ 注意：同一バージョンのパラメータ変更とバージョン更新を分ける
v2.9.10の料金しきい値やDry Runだけを変更する場合は、現在のテンプレートを使用して変更セットを作成します。ソリューションのバージョンを更新する場合は、更新先バージョンの公式テンプレートを指定し、リリースノート、リソースの置換・削除、IAM差分および引き継ぐパラメータを確認します。 料金しきい値とDryRunは、CloudFormationスタックsample-cfn-co-001のパラメータとして管理します。設定変更は CloudFormation変更セット を使用し、事前に差分を確認してから実行します。

ECSタスク定義、EventBridge、IAM、S3等を直接編集するとCloudFormationの管理状態と実リソースに差分が生じるため、通常運用では行いません。

管理範囲

作業開始前の確認

DryRun=No にすると、以後の日次実行で判定条件を満たしたWorkSpaceの課金モード変更が実行されます。スタック更新直後に即時実行されるわけではありません。

本番環境では次を満たしてから解除します。

  • DryRunの日次・月次レポートを十分な期間（推奨は数か月）確認済みです。
  • 料金しきい値と対象リージョンがお客様承認済みです。
  • 自動変更対象から除外するWorkSpaceに Skip_Convert タグを設定済みです。
  • TerminateUnusedWorkspaces=No を確認済みです。終了機能を利用する場合は別途承認します。
  • 次回自動実行時刻と、同一UTC日内に実行済みでないことを確認済みです。
  • 切り戻し手順と変更承認を確認済みです。

運用作業

1. 変更前の値を確認する

  1. CloudFormationで東京リージョンを選択します。
  2. スタックsample-cfn-co-001を開きます。
  3. 「パラメータ」または「出力」で、変更前が DryRun=Yes となっていることを確認します。

2. 変更セットを作成する

  1. 「スタックアクション」から「現在のスタックの変更セットを作成」を選択します。
  2. テンプレートは「現在のテンプレートを使用」を選択し、「次へ」を選択します。
  1. Launch in Dry Run Mode を No に変更します。
  2. Terminate unused workspaces=No、TestEndOfMonth=No および他のパラメータが意図せず変わっていないことを確認します。
  1. 「プロビジョニング失敗時の動作」は「すべてのリソースをロールバック」とします。
  2. 検証オプションに意図しない変更がないことと、IAMリソースの作成に関する承認欄を確認します。

3. 差分を確認して実行する

  1. 変更セット名、説明、変更理由、承認者を記録します。
  2. 変更セットを作成します。
  3. 取得例ではCostOptimizerTaskDefinitionがModify・置換True（ReplaceAndDelete）、ScheduleRuleがModify・置換Falseでした。実作業では使用中のテンプレートと変更パラメータに対する差分を確認します。
  4. 意図しない削除・置換がないことを確認します。
  1. 「変更セットを実行」を選択して確認画面を開きます。
  2. ロールバック設定を最終確認し、確認画面の「変更セットを実行」を選択します。

4. 更新結果を確認する

  1. CloudFormationが UPDATE_COMPLETE になるまで待ちます。
  2. 失敗イベントがないことを確認します。

コンテナイメージ自動更新の注意

  1. CloudFormationスタック出力の SolutionVersion
  2. ECSタスク定義のコンテナイメージURI
  3. 厳密な再現性が必要な場合は、実行タスクのイメージダイジェスト

固定リリースイメージのみを使用する場合は Auto-update Container Image=No とします。ただし、同一マイナーバージョン内のセキュリティ更新を自動取得しなくなるため、更新管理方法を別途定める必要があります。

実行結果を確認する際の注意

CloudWatchダッシュボードは、分析対象数、変更結果、コンテナ実行状況などを把握するための可視化画面です。作成直後やメトリクス送信前は空欄となる場合があります。

処理成功の確認では、次の3点を併せて確認します。

  1. ECSタスクが起動し、異常終了していないこと
  2. CloudWatch Logsの対象実行ログにエラーがないこと
  3. ソリューションが作成したS3バケットへ対象日のCSVレポートが保存されていること

CSVが作成されていても、各WorkSpaceの課金モードが変更されたとは限りません。Change Reported、Initial Mode、New Mode、および必要に応じてECSログを確認してください。変更失敗またはスキップがある場合は、日次レポートの結果とECSログの例外内容を照合します。
