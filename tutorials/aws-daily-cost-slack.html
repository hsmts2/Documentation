AWS利用料を毎朝3時にSlackへ通知する

Cost Explorerの前日利用料、サービス別内訳、当月累計を毎日03:00 JSTにSlackへ送る構成をまとめる
Slack Incoming Webhook、IAM、Parameter Store、Lambda、EventBridge Schedulerの設定と検証手順を実際の構成に沿って示す

今回実現した構成

EventBridge Schedulerが毎日03:00 JSTにLambdaを起動する。LambdaはCost ExplorerからUSD建ての概算利用料を取得し、月ごとに固定したECB参考レートで円換算して、Slackの表ブロックで投稿する

項目設定値
AWSリージョンAsia Pacific (Tokyo) ap-northeast-1
CloudFormationスタックaws-daily-cost-slack
Lambda実行ロールaws-costs-role
LambdaPython 3.13、128 MB、タイムアウト30秒
スケジュールcron(0 3 * * ? *)、Asia/Tokyo、Flexible time window無効
Slack投稿先#aws-costs（Incoming Webhook）
Webhook保管先SSM Parameter Store /daily-cost-slack/webhook、SecureString
月次レート保管先SSM Parameter Store /daily-cost-slack/fx/YYYY-MM、String
料金データCost Explorer UnblendedCost、日次、サービス別。APIクライアントはus-east-1
⚠️ 注意

Cost Explorerの数値は概算で、反映遅延や後日の調整がある。円換算はECB参考レートによる表示で、税やAWSの確定請求額とは一致しない

1. Slack Incoming Webhookを作成

  1. Slack APIのアプリ管理画面でAWS Daily Costアプリを作成し、対象ワークスペースを選択
  2. Incoming Webhooksを開いてActivate Incoming Webhooksを有効化
  3. Add New Webhookから投稿先の#aws-costsを選択して許可
  4. 発行されたWebhook URLを安全な一時保管場所へ控え、次の手順でParameter Storeへ登録
⚠️ 注意

Webhook URLそのものが投稿権限を持つ秘密情報。URL、コピー用curlコマンド、Parameter Storeの値をスクリーンショットやGitへ載せない

2. WebhookをParameter Storeへ保存

Systems ManagerのParameter Storeでパラメータを作成する。名前は/daily-cost-slack/webhook、タイプはSecureString、暗号化キーはAWS管理キーaws/ssmとする。値欄へ前手順で取得したWebhook URLを入力して保存する

月次レートの/daily-cost-slack/fx/YYYY-MMはLambdaが初回実行時にStringとして作成するため、手動で作らない

3. Lambda実行ロールを作成

IAMで信頼されたエンティティにLambdaを選び、ロール名aws-costs-roleを作成する。AWS管理ポリシーAWSLambdaBasicExecutionRoleでCloudWatch Logsへの出力を許可する

料金の読み取り、Webhookと月次レートの読み取り、月次レートの保存に必要なアクションだけをインラインポリシーへ追加する。次の<AWS_ACCOUNT_ID>は自分のAWSアカウントIDへ置き換える

json
{
  "Version": "2012-10-17",
  "Statement": [
    {"Sid": "ReadCostExplorer", "Effect": "Allow", "Action": "ce:GetCostAndUsage", "Resource": "*"},
    {"Sid": "ReadWebhookAndMonthlyRate", "Effect": "Allow", "Action": "ssm:GetParameter", "Resource": [
      "arn:aws:ssm:ap-northeast-1:<AWS_ACCOUNT_ID>:parameter/daily-cost-slack/webhook",
      "arn:aws:ssm:ap-northeast-1:<AWS_ACCOUNT_ID>:parameter/daily-cost-slack/fx/*"
    ]},
    {"Sid": "StoreMonthlyRate", "Effect": "Allow", "Action": "ssm:PutParameter",
      "Resource": "arn:aws:ssm:ap-northeast-1:<AWS_ACCOUNT_ID>:parameter/daily-cost-slack/fx/*"}
  ]
}

aws/ssm管理キーを使用した今回の構成では、別途カスタマー管理KMSキーの復号権限は付けていない。カスタマー管理キーへ変える場合は、そのキーのポリシーとkms:Decryptを再確認する

4. SAMでLambdaとスケジュールを配置

SAM CLIを導入し、app.pyとtemplate.yamlを同じディレクトリに置く。実際に配置した定義は次のとおり

yaml
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: Daily estimated AWS costs to a private Slack channel
Parameters:
  WebhookParameterName:
    Type: String
    Default: /daily-cost-slack/webhook
Resources:
  DailyCostFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: .
      Handler: app.lambda_handler
      Runtime: python3.13
      Role: !Sub arn:${AWS::Partition}:iam::${AWS::AccountId}:role/aws-costs-role
      Timeout: 30
      MemorySize: 128
      Environment:
        Variables:
          WEBHOOK_PARAMETER_NAME: !Ref WebhookParameterName
          FX_PARAMETER_PREFIX: /daily-cost-slack/fx
      Events:
        EveryMorning:
          Type: ScheduleV2
          Properties:
            ScheduleExpression: cron(0 3 * * ? *)
            ScheduleExpressionTimezone: Asia/Tokyo
            FlexibleTimeWindow:
              Mode: 'OFF'

ローカルの作業ディレクトリでビルドし、AWSアカウントとリージョンを確認してから配置する

powershell
aws sts get-caller-identity
powershell
sam build
powershell
sam deploy --guided

sam deploy --guidedではスタック名aws-daily-cost-slack、リージョンap-northeast-1を指定し、変更セットとIAM関連の確認を行う。配置後、EventBridge SchedulerのスケジュールがENABLEDで、時刻がcron(0 3 * * ? *)／Asia/Tokyoか確認する

5. Lambdaで料金を集計し、表形式で送信

配置したLambdaの全コード（app.py）とSAMテンプレート（template.yaml）を掲載する。以下はSlackの列ずれをなくすために使用した表ブロックの部分

python
rows = [["サービス", "利用料", "日本円"]]
rows.extend([SERVICE_NAMES.get(name, name), f"${amount:.2f}",
             f"{yen(amount, rate):,}円" if rate else "-"] for name, amount in shown)
blocks.append({
    "type": "table",
    "column_settings": [{"align": "left"}] * 3,
    "rows": [[{"type": "raw_text", "text": cell} for cell in row] for row in rows],
})

半角スペースの個数で表を揃える方式は、日本語と英数字が混在するとSlackの表示環境によってずれる。Slackのtable Block Kitブロックなら、見出しと金額をそれぞれの列に配置できる。textには表非対応環境向けのフォールバックも含める

Cost ExplorerではUnblendedCostを日次・サービス別に取得し、前日の上位5サービスと残額の「その他」、その月の前日までの合計を算出する。表示名が長いAmazon Virtual Private CloudはAmazon VPC、AWS Secrets ManagerはSecrets Managerへ短縮する

参考換算レートはECBのUSDとJPYの公表値から計算し、報告対象月の初回投稿時にSSMへ保存する。同じ月の通知では保存済みレートを再利用する。ECB取得に失敗したときはUSDのみを表示する

6. テスト送信と運用確認

  1. Lambdaのテストイベントに{}を設定して実行
  2. 実行結果がstatus: sentで、#aws-costsに1件届いたことを確認
  3. サービス、利用料、日本円の列がSlackで縦に揃い、前日の日付と月次累計が表示されることを確認
  4. CloudWatch Logsでエラーがないことと、SchedulerがENABLEDであることを確認

Lambdaの手動テストもCost Explorer APIを呼び、実際にSlackへ投稿する。テストのたびに通知が増え、APIリクエストにも料金が発生し得るため、連続実行には注意する

出典：AWS SAM ScheduleV2、Slack Incoming Webhooks、Slack Table Block
