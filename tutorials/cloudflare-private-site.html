Private GitHubリポジトリをCloudflare Workersで認証付き公開してみた

GitHubで管理する静的ドキュメントをCloudflare Workersへ自動デプロイし、Cloudflare AccessとAuthenticatorアプリのMFAで閲覧を保護した手順をまとめる
リポジトリ連携、公開ファイルの分離、Access設定、Private化、自動デプロイと最終URLの確認までを実際の構成に沿って整理する

今回実現した構成

ソースはPrivateのGitHubリポジトリで管理し、mainへのPushをCloudflare Workers Buildsが検知して静的ファイルだけをWorkersへデプロイする
閲覧時はCloudflare Accessで本人確認を行い、AuthenticatorアプリのTOTPを追加認証として必須にする

Private GitHubリポジトリ→ Push Workers Builds→ Deploy Cloudflare Workers→ Access Authenticator MFA
対象今回の設定目的
GitHubリポジトリPrivateソースコードと画像を一般公開しない
デプロイ元ブランチmain確定した変更だけを自動公開する
ホスティングCloudflare Workers Static Assets静的HTML、CSS、JavaScript、画像を配信する
閲覧制御Cloudflare Access認証を通過した利用者だけに公開する
多要素認証AuthenticatorアプリのTOTPメールを受信できない端末でも6桁コードで本人確認する
⚠️ Privateリポジトリと非公開サイトは別

GitHub Pagesは、利用プランや構成によってPrivateリポジトリから公開できても、サイト自体がインターネットへ公開される。ソースの非公開化だけで閲覧制御まで完了したと判断せず、Cloudflare Accessの認証を別に設定する

出典：GitHub Pagesの公開ソースとサイト公開範囲

1. GitHubリポジトリをCloudflareへ連携

Cloudflare Workers and PagesのGitHub Appをインストールし、連携対象を必要なリポジトリだけへ限定する
All repositoriesではなくOnly select repositoriesを選択し、Documentationだけを指定する

  1. CloudflareダッシュボードでWorkers & Pages ＞ アプリケーションを作成するを選択
  2. GitHubアカウントを選択し、Cloudflare Workers and PagesのGitHub Appを開く
  3. Only select repositoriesを選択し、公開元のリポジトリだけを追加
  4. 表示される権限と対象リポジトリを確認し、Install & Authorizeを選択

2. Workersアプリケーションを作成

連携したGitHubアカウントからDocumentationを選択し、Workersアプリケーションを作成する
プロジェクト名はdocumentation、Production branchはmain、Root directoryは/とする

  1. CloudflareダッシュボードでWorkers & Pages ＞ アプリケーションを作成するを開く
  2. リポジトリを選択するでDocumentationを選択
  3. プロジェクト名、Production branch、ビルドコマンド、デプロイコマンドを入力
  4. 非本番ブランチからの自動デプロイを使用しない場合は、Non-production branch buildsを無効化

出典：Workers Buildsの構成

3. 公開するファイルだけをデプロイ

リポジトリ直下をそのまま公開対象にせず、ビルド時にdistを作成してHTML、CSS、JavaScript、画像だけをコピーする
この構成により、.git、README.md、CONTRIBUTING.md、検査スクリプトをWorkersへアップロードしない

設定項目設定値
Build commandmkdir dist && cp ./*.html dist/ && cp -r assets tutorials dist/
Deploy commandnpx wrangler deploy --assets=dist --compatibility-date 2026-09-03
Root directory/
Production branchmain
Non-production branch buildsOFF

Build commandへ次の内容を設定

bash
mkdir dist && cp ./*.html dist/ && cp -r assets tutorials dist/

Deploy commandへ次の内容を設定

bash
npx wrangler deploy --assets=dist --compatibility-date 2026-09-03
❌ --assets=.は指定しない

リポジトリ直下をStatic Assetsとして指定すると、公開を意図していない管理ファイルまでアップロード対象になる。先に公開専用ディレクトリを作成し、--assets=distのように対象を限定する

出典：Cloudflare Workers Static Assets

4. Cloudflare Accessでサイトを保護

WorkersアプリケーションのAccessから保護を有効化し、Production URLとPreview URLを認証対象にする
Zero Trustの利用プランはZero Trust Freeを選択し、組織名とApp Launcherを作成する

  1. Workers & Pages ＞ documentation ＞ Accessを開く
  2. Protect with Cloudflare Accessを有効化
  3. 保護範囲でProduction URLとPreview URLを選択
  4. Cloudflare Oneの初期設定を開き、Zero Trust Freeを選択
  5. Access applicationのAllowポリシーへCloudflare account membersを指定

5. AuthenticatorアプリのMFAを必須化

Cloudflare AccessのIndependent MFAを有効化し、許可する方式をAuthenticator applicationだけに限定する
サイト用アプリケーションのMFAをCustom、セッション時間を24 hoursとして保存する

  1. Cloudflare Oneで設定 ＞ 認証 ＞ MFAを開く
  2. Independent MFAでAuthenticator applicationを許可
  3. App LauncherのAccount ＞ MFA devices ＞ Add an MFA deviceを開く
  4. AuthenticatorアプリでQRコードを読み取り、表示された6桁コードで登録
  5. 対象Access applicationのMFAをCustomへ変更し、Authenticator applicationだけを必須化
⚠️ MFA登録情報を記録・公開しない

QRコードとセットアップキーはTOTPの共有秘密であり、第三者が取得すると同じワンタイムコードを生成できる。登録画面を掲載する場合は、QRコード、セットアップキー、入力した6桁コードを復元できない不透明な図形で完全にマスクする

出典：Cloudflare Access Independent MFA

6. GitHubリポジトリをPrivateへ変更

Cloudflareからの初回デプロイとAccess認証を確認した後、GitHubリポジトリをPrivateへ変更する
先にGitHub Appの対象へリポジトリを追加しておくことで、Private化後もWorkers Buildsがソースを取得できる状態を維持する

  1. GitHubの対象リポジトリでSettings ＞ Generalを開く
  2. Danger Zone ＞ Change repository visibilityを選択
  3. Make privateを選択し、対象リポジトリ名を確認して確定
  4. ログアウト状態でGitHubのリポジトリURLを開き、ソースを閲覧できないことを確認
ℹ️ GitHub Pagesの扱い

個人アカウントのGitHub Freeで公開中のPagesサイトは、リポジトリをPrivateへ変更すると自動的に非公開化される。今回は公開先をCloudflare Workersへ切り替え、旧GitHub Pages URLが表示されないことも確認する

出典：GitHubリポジトリの可視性変更

7. Private化後の自動デプロイを確認

mainへ変更をPushし、Workers BuildsがPrivateリポジトリをCloneしてBuild commandとDeploy commandを順に実行できることを確認する
今回の検証では171ファイルを読み込み、23秒でデプロイが完了した

確認対象確認結果
GitHubリポジトリPrivate化後、未認証アクセスは404
旧GitHub Pages URL未公開となり404
Workers URL未認証アクセスはCloudflare Accessへ302リダイレクト
Access認証Cloudflareアカウント認証とAuthenticator MFAの通過後にDocumentationを表示
Private化後のPushWorkers Buildsが自動実行され、正常にデプロイ
