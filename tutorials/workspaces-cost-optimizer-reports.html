Cost Optimizerのレポート・監視

仕様

構成・動作

日次実行のECSタスク、ログ、CSVとWorkSpaces実行モードを照合します。

管理範囲

設定値は取得時点の検証例です。実作業では承認済みパラメータと現在のAWS環境を確認します。

制約事項

取得済みのCSVと画面はDryRun=Yesの実測1台分です。説明用5台データは実測結果に含めません。

前提条件

既存リソース・ネットワーク

対象のCloudFormationスタック、ECSクラスター、CloudWatch Logs、レポート用S3バケットが存在することを確認します。

権限・接続環境

監視担当者にはECS、CloudWatch Logs、S3、WorkSpacesの参照権限を付与します。SCP、アクセス許可境界、明示的な拒否による制限も確認します。

事前に準備する情報

項目確認内容
対象スタックsample-cfn-co-001（検証例。実作業では現在の対象を確認）
取得済みレポートDry Run有効時・1台分
Dry Run解除後の結果未確認

運用作業

1. 確認対象

Cost Optimizerの1回の処理は、主に次の場所で確認します。

確認先 確認内容 今回の確認先
Amazon ECS 起動したタスク、停止理由、終了コード クラスター cost-optimizer-cluster
CloudWatch Logs 読み込んだパラメータ、走査リージョン、処理結果、例外 /ecs/wco-task/sample-cfn-co-001
Amazon S3 リージョン／ディレクトリ別CSV、集約CSV sample-cfn-co-001-costoptimizerbucket-yirana73nt26
CloudWatch dashboard 台数、課金形態、変換、終了、失敗、処理時間 sample-cfn-co-001-Dashboard-b3cb8f30-ab0e-11f1-b7e4-0e752dcc785b

2. ECSタスクを確認する

  1. ECSで cost-optimizer-cluster を開きます。
  2. 「タスク」で対象時刻のタスクを選択し、使用したタスク定義のリビジョンと実行情報を確認します。
  3. タスクがSTOPPEDとなっていること、停止理由とコンテナ終了コード0を確認します。終了コード0でも処理対象の一部にエラーが残る場合があるため、対象リージョンのログを続けて確認します。

3. CloudWatchダッシュボードを確認する

  1. CloudWatchの「ダッシュボード」を開きます。
  2. sample-cfn-co-001-Dashboard-b3cb8f30-ab0e-11f1-b7e4-0e752dcc785b を選択します。
  3. 対象期間を実行時刻が含まれる範囲にします。
  4. 総WorkSpaces数、Hourly／Monthly、DryRun／実変換、終了、失敗・スキップ、ECS処理時間を確認します。

取得済み証跡では総数1、Hourly 1、Monthly 0を確認しました。変換や終了がなければ該当ウィジェットが空になることは正常です。

4. S3レポートを確認する

  1. CloudFormationスタックの「出力」で BucketName を確認します。
  2. バケットを開き、YYYY/MM/DD/ の順に対象日を開きます。
  3. 当日の処理で新規作成された集約版とリージョン／ディレクトリ別CSVを確認します。今回DryRun=Yesの実行で確認した名称は、aggregated_dry-run_daily.csv と ＜リージョン＞_＜アカウント＞_＜ディレクトリ＞_dry-run_daily.csv です。
  4. CSVをダウンロードし、文字化けや列ずれがなく開けることを確認します。

取得済み証跡では2026/09/08/に、09:01 JST（00:01 UTC）付近で2種類のCSVが保存されました。運用確認では固定日付を使用せず、対象実行日と実際のECS終了時刻に対応するプレフィックスを確認します。

⚠️ 注意：掲載証跡はDry Run有効時の結果
図4・図5および実測CSVは DryRun=Yes 時の1台分の結果です。DryRun=No へ変更した後の実変更結果ではありません。 DryRun=No の実運用確認では、名称を決め打ちせず、対象日の実行時刻以降に作成されたCSVのファイル名と内容を確認します。

5. CSVの主な列を確認する

列 見方
WorkspaceID 対象WorkSpace ID
Billable Hours 当月の請求対象時間
Usage Threshold 対象バンドルに適用したしきい値
Change Reported 判定または変更内容。DryRun時は実変更を意味しない
Initial Mode 実行前の課金モード
New Mode 判定後の課金モード
WorkspaceTerminated 終了判定の結果
Tags 除外タグ等の確認
ReportDate レポート対象日

DryRun=No の実行後はCSVだけで完了判定せず、WorkSpacesコンソールの課金モードも照合します。CSVに Failed to change mode 等がある場合は、同時刻のCloudWatch Logsを確認します。

6. ダッシュボードの台数・変換結果を確認する

監視対象台数、課金モードの変換件数、Dry Runおよび実際の終了件数の時系列を確認します。

7. CloudWatch Logsを確認する

  1. CloudWatchの「ロググループ」で /ecs/wco-task/sample-cfn-co-001 を開きます。
  2. 実行時刻に対応するログストリームを開きます。
  3. DryRun、料金しきい値、Regions、TerminateUnusedWorkspaces 等が意図した値か確認します。
  4. ERROR、Exception、Traceback、AccessDenied、UnrecognizedClientException、Failed to change mode を検索します。
  5. 対象リージョンの走査、WorkSpaces件数、CSV出力、完了ログを確認します。

ロググループの保持期間は365日です。

取得済み証跡ではRegionsが空欄で、アカウントで未有効化のリージョンにUnrecognizedClientExceptionが記録されましたが、東京リージョンの処理とCSV出力は完了しました。運用範囲が決まっている場合は、CloudFormationパラメータRegionsに必要なリージョンのみを指定します。Failed to change modeがある場合はWorkSpace IDで同じログを検索し、状態や例外を確認します。次回の日次実行で再試行されるため、その結果も確認します。

運用後確認

  • 対象実行のECSタスクが正常終了していること。
  • 対象日のS3 CSVが生成され、内容を開けること。
  • 対象リージョンのログに未解決のエラーがなく、実行パラメータを確認できること。

対象データ

本資料は、Cost Optimizer for Amazon WorkSpacesが出力するCSVの項目と、複数台を並べた場合の見方を説明するための補助資料です。

Excelブックの見方

説明用サンプル_5台_WorkSpacesCostOptimizer.xlsx は、次の3シートで構成されています。

「概要」シート

5台のサンプル全体を確認するシートです。

  • 対象WorkSpaces：5台
  • Billable Hours合計：184時間
  • 変更報告数：0件
  • Bundle Type別のBillable HoursとUsage Thresholdをグラフで比較

台数、合計時間、変更報告数は「サンプル明細」を参照する数式で計算されています。グラフはVALUE、STANDARD、PERFORMANCE、POWER、POWERPROの5種類を説明するためのもので、実環境のバンドル構成比を表すものではありません。

「料金パラメータ比較」シート

お客様環境で確認したv2.8.1の料金しきい値と、本手順書でv2.9.10へ設定した値を比較するシートです。

比較列は「手順書設定値」と表示しています。これは、2026年9月8日時点のAWS実装ガイドに掲載され、本手順書で採用した設定値です。v2.9.10配布テンプレート内の既定値とは同義ではありません。両者の差分は、参考_v2.8.1-v2.9.10差分.md を正として確認してください。

このシートは料金しきい値の違いを説明するために使用します。実際の料金変更判断では、利用リージョンのAmazon WorkSpaces料金、お客様環境の使用状況、Dry Runレポートを別途確認します。

「サンプル明細」シート

5台分のCSV列を横並びで確認するシートです。主な列は次のとおりです。

列 確認内容
WorkspaceID 対象WorkSpace。サンプルでは ws-sample001 から ws-sample005 の架空ID
Billable Hours 当月の課金対象時間としてレポートされた値
Usage Threshold バンドル種別に対応する料金しきい値
Change Reported 課金モード変更の判定結果
Initial Mode／New Mode 判定前後の課金モード
WorkspaceTerminated 未使用WorkSpace終了機能による終了結果
パフォーマンス関連列 遅延、CPU、メモリ、ディスク、UDPパケット損失率などの説明用値
WorkspaceType PRIMARY／STANDBYの識別
ReportDate レポート日付

サンプル5台はすべて Change Reported=No Change、Initial Mode=AUTO_STOP、New Mode=AUTO_STOP としています。これは列の読み方を説明するための設定です。課金モード変更が実際に成功したことを示すものではありません。

実行結果を確認する際の注意

CloudWatchダッシュボードは、分析対象数、変更結果、コンテナ実行状況などを把握するための可視化画面です。作成直後やメトリクス送信前は空欄となる場合があります。

処理成功の確認では、次の3点を併せて確認します。

  1. ECSタスクが起動し、異常終了していないこと
  2. CloudWatch Logsの対象実行ログにエラーがないこと
  3. ソリューションが作成したS3バケットへ対象日のCSVレポートが保存されていること

CSVが作成されていても、各WorkSpaceの課金モードが変更されたとは限りません。Change Reported、Initial Mode、New Mode、および必要に応じてECSログを確認してください。変更失敗またはスキップがある場合は、日次レポートの結果とECSログの例外内容を照合します。
