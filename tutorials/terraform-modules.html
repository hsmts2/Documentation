ルートモジュールと子モジュール

Terraformを実行するフォルダーがルートモジュール。そこからmoduleブロックで指定する部品が子モジュール。子へは入力変数を渡し、結果はoutput経由で受け取る

配置例
module-lab/
  envs/
    dev/
      main.tf
  modules/
    queue/
      main.tf
      variables.tf
      outputs.tf

同じルートから呼び出した子モジュールは同じStateで管理。モジュール化だけではdev／prodのState・アクセス権は分離されない

① 既存のqueue-labとは別の検証フォルダーを作成。既に存在する場合は別名を使用

PowerShell
New-Item -ItemType Directory -Path "$env:USERPROFILE\IaC\Terraform\module-lab"
Set-Location "$env:USERPROFILE\IaC\Terraform\module-lab"
New-Item -ItemType Directory -Path "envs\dev", "modules\queue"

子モジュールの作成

VS Codeでmodules/queueに次のファイルを保存。接続先や認証を決めるproviderブロックは子モジュールへ埋め込まず、ルートで設定

modules/queue/main.tf
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = ">= 6.0, < 7.0"
    }
  }
}

resource "aws_sqs_queue" "this" {
  name                    = var.name
  max_message_size        = var.message_size
  sqs_managed_sse_enabled = true
  tags                    = var.tags
}
modules/queue/variables.tf
variable "name" {
  type        = string
  description = "Queue name"
}

variable "message_size" {
  type        = number
  description = "Maximum message size in bytes"
  default     = 2048
}

variable "tags" {
  type        = map(string)
  description = "Resource tags"
  default     = {}
}
modules/queue/outputs.tf
output "url" {
  description = "Queue URL"
  value       = aws_sqs_queue.this.url
}

required_providersは子でも宣言。Providerのsourceとバージョン条件を指定する宣言であり、接続設定そのものではない

ルートからの呼び出し

envs/dev/main.tfへ次を保存。sourceは呼び出し元フォルダーを基準とする相対パス。ローカルモジュールではversion引数を使用しない

envs/dev/main.tf
terraform {
  required_version = ">= 1.10, < 2.0"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = "ap-northeast-1"
}

module "queue" {
  source       = "../../modules/queue"
  name         = "tf-module-dev"
  message_size = 2048
  tags = {
    Environment = "dev"
    ManagedBy   = "Terraform"
  }
}

output "queue_url" {
  value = module.queue.url
}

module.queue.urlは子のoutputを参照する記法。子の内部リソースを呼び出し元から直接参照せず、必要な値をoutputとして公開

初期化・計画・適用

① envs/devへ移動し、接続先を確認

PowerShell
Set-Location "$env:USERPROFILE\IaC\Terraform\module-lab\envs\dev"
$env:AWS_PROFILE = "iac-admin"
aws sts get-caller-identity --profile iac-admin

② 子モジュールを読み込み、構文を検証。module追加やsource変更後はinitを再実行

PowerShell
terraform init
terraform validate

③ Planを保存。追加対象がtf-module-devのキューだけであることを確認

PowerShell
terraform plan -out=module.tfplan

④ 確認済みの計画を適用。保存済みPlanを指定するため再確認なしで実行

PowerShell
terraform apply module.tfplan

⑤ 出力とStateを確認。アドレスにmodule.queueが付くことを確認

PowerShell
terraform output queue_url
terraform state list
terraform plan

子の値を変更する場合は呼び出し側のmessage_size等を変更し、再びPlanをレビュー。片付けは同じenvs/devから削除手順を実施

⚠️ 注意

既に作成したリソースをコードだけ子モジュールへ移すと、削除・再作成が提案される場合がある。移設時はmovedブロックでState上の対応も変更

公開モジュールの利用

Terraform Registryで用途に合うモジュールを探し、選択したバージョンのドキュメントを確認。モジュール名だけで採用せず、次の内容を確認

確認項目確認する内容
Inputs必須入力、既定値、validation、リソース作成の切り替え
Outputs他の構成へ渡す値
ResourcesNAT Gateway・ロードバランサー等を含む実際の作成対象
DependenciesTerraform・Provider・子モジュールの要件
README・Examples必要権限、前提ネットワーク、利用可能な構成
ソース・更新履歴管理者、変更内容、ライセンス、非互換変更

RegistryのUsageを基にmoduleブロックを作成し、sourceとversionを明示。以下は置換が必要な記法例であり、そのまま実行するサンプルではない

HCL：Registryモジュールの指定形式
module "network" {
  source  = "<NAMESPACE>/<NAME>/<PROVIDER>"
  version = "<MODULE_VERSION>"
  # 選択したモジュールの必須入力を追加
}

Gitリポジトリから取得する場合はsourceのrefでタグまたはコミットを固定。Registryのversion引数とは別の仕組み

HCL：Git取得の指定形式
module "network" {
  source = "git::https://github.com/<OWNER>/<REPOSITORY>.git//modules/network?ref=<COMMIT_SHA>"
}

.terraform.lock.hclが固定する対象はProvider。リモートモジュールのバージョンはmodule側で管理し、変更前後のPlanも確認

モジュールの共有・公開

① main.tf・variables.tf・outputs.tfを基本構成とし、READMEに入力、出力、作成リソース、必要権限、削除時の影響を記載。examplesには単独で検証できる呼び出し例を用意

② モジュールのルートで整形を確認

PowerShell
terraform fmt -check -recursive

③ 呼び出し例のルートでinit／validate／Planを確認。terraform testを使う場合はrunの実行方式と作成されるリソースを確認し、業務環境の認証を渡さない

④ terraform-aws-queueのようなリポジトリ名でVCSへ配置。認証情報・State・Planを含めないことを確認し、リリース用のバージョンタグを付与

⑤ HCP TerraformのPrivate RegistryでPublishからModuleを選択し、VCSとモジュールのリポジトリを指定。取得されたバージョン、Inputs、Outputsを確認。画面の項目名が異なる場合はModule登録の項目を選択

⑥ 表示されたUsageを呼び出し元へ設定し、認証後にinitを実行。更新は全環境で一括ではなく、検証環境でPlanを確認してから順次反映

公開Registryはソースや説明が外部へ公開されるため、社内用モジュールはPrivate Registryまたはアクセス制御されたVCSで共有
