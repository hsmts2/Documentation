コミット済みの変更を打ち消す

共有済みの変更を取り消す場合は、過去の履歴を削除するのではなく、逆の変更を新しいコミットとして追加するrevertを使用。以下は通常の1親コミットを対象とする操作例で、実施ログではない

1. 未コミットの変更がないことを確認

Git Bash（操作例）
git status

2. 打ち消すコミットと影響を確認。<COMMIT>は対象のIDへ置換

Git Bash（操作例）
git show <COMMIT>

3. 対象コミットを打ち消す変更を作成。エディタが開いた場合は内容を確認・保存して閉じる

Git Bash（操作例）
git revert <COMMIT>

4. 新しい取り消しコミットを確認

Git Bash（操作例）
git log --oneline -2

5. 作業状態を確認

Git Bash（操作例）
git status

競合時は編集・保存・git addの後にgit revert --continueで続行。中止する場合はgit revert --abortを選択。マージコミットは親の選択が必要なため、この手順をそのまま適用しない

見失ったコミットを探す

reflogは、このローカルリポジトリでHEADやブランチを移動した記録。GitHubの共有履歴とは別で、期限切れやクリーンアップにより消えるため恒久的なバックアップではない

1. HEADの移動記録を確認する操作例

Git Bash（操作例）
git reflog

2. 候補のコミットが必要な内容か確認

Git Bash（操作例）
git show <COMMIT>

3. 必要なコミットを指す新規ブランチを作成して保全。rescue/recoveredが未使用であることを確認

Git Bash（操作例）
git branch rescue/recovered <COMMIT>

4. 保全したブランチの履歴を確認

Git Bash（操作例）
git log --oneline rescue/recovered -5

ここでは現在の作業ファイルを上書きせず、参照だけを作成。確認前にreset --hardで現在の変更を破棄しないこと

特定のコミットだけを取り込む

cherry-pickは指定したコミットの変更を現在のブランチへ適用する操作。ブランチ全体を統合するmergeとは異なり、通常は別IDのコミットを作成。前提となる変更が不足していないかも確認

1. 現在の変更状態を確認し、未コミットの変更がない状態にする

Git Bash（操作例）
git status

2. 取り込み先へ移動。<TARGET_BRANCH>を置換

Git Bash（操作例）
git switch <TARGET_BRANCH>

3. 取り込むコミットの差分を確認

Git Bash（操作例）
git show <COMMIT>

4. 指定した通常の1親コミットの変更を適用

Git Bash（操作例）
git cherry-pick <COMMIT>

5. 適用後の履歴を確認

Git Bash（操作例）
git log --oneline -2

競合時は編集・保存・git addの後にgit cherry-pick --continueで続行。取り込みを中止する場合だけgit cherry-pick --abortを使用。成功後にabortを実行する手順ではない

秘密情報をコミットした場合

鍵・トークン・パスワードを公開した可能性がある場合、ファイルの削除だけでは過去のコミットから消えない。まず発行元で無効化・再発行し、影響範囲と不正利用の有無を確認

その後、現行ファイルから削除し、秘密値を環境変数やシークレット管理へ移動。既に追跡中のファイルは.gitignoreへ追記するだけでは追跡が解除されない

履歴からの除去が必要な場合は管理者・共同作業者と調整し、fork・clone・ログ・成果物も調査。共有履歴の書き換えや強制pushを単独で実施しないこと

認証方法はGitHub認証、強制pushの注意はGitリモート操作を参照
