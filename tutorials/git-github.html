Git / GitHub

Git / GitHub 概要

初期設定

1. Gitのインストール

Gitのバージョンを確認

Git Bash / PowerShell
git --version

Git for Windowsの公式ページから、インストーラーをダウンロードし実行

出典：Git for Windowsの公式インストールページ

PowerShellを起動し、WinGetでGitをインストール

PowerShell
winget install --id Git.Git -e --source winget

インストール完了後にGit BashまたはPowerShellを起動し、バージョンを再確認

Git Bash / PowerShell
git --version

出典：Git公式：Install for Windows

ℹ️ Git BashとPowerShellの違い

Git BashとPowerShellはWindows上で動作するシェルで、基本的なGitコマンドは共通する一方、ファイル操作やパス表記に違いがあり、内容表示にはそれぞれcat、Get-Contentを使用

2. コミットに記録する名前・メールの設定

コミットに記録する名前を設定（t_hashimotoは例示値のため、必要に応じて変更）

Git Bash / PowerShell
git config --global user.name "t_hashimoto"

コミットに記録するメールを設定（t_hashimoto@example.comは例示値のため、必要に応じて変更）

Git Bash / PowerShell
git config --global user.email "t_hashimoto@example.com"

名前・メールはGitHubのログイン情報ではなく、コミットの記録者情報として設定し、--globalで現在のユーザーに共通適用（リポジトリ固有の設定を優先）、通常は~/.gitconfigに保存されるため再起動後の再設定は不要

出典：Git公式：First-Time Git Setup

3. 初期ブランチ名の設定

新規リポジトリの初期ブランチ名をmainに設定（設定済みの場合は不要）

Git Bash / PowerShell
git config --global init.defaultBranch main

git initによる新規作成時に適用（既存ブランチへの影響なし）

出典：Git公式：git init

4. 使用するエディタの設定

VS Codeのcodeコマンドが利用可能か確認

Git Bash / PowerShell
code --version

Gitで使用するエディタにVS Codeを設定

Git Bash / PowerShell
git config --global core.editor "code --wait"

--waitはファイルを閉じるまで待機する指定（他のエディタは起動コマンドを変更）

出典：Git公式：Setup and Config

5. 設定結果の確認

名前、メール、初期ブランチ名、エディタのグローバル設定を確認

Git Bash / PowerShell
git config --global user.name
git config --global user.email
git config --global init.defaultBranch
git config --global core.editor
実行結果
実行結果（例）
t_hashimoto
t_hashimoto@example.com
main
code --wait

core.editorが空ならグローバル設定は未設定（別の設定や既定のエディタを使用）

読み込み元の設定ファイルと設定値を確認

Git Bash / PowerShell
git config --list --show-origin

リポジトリ固有の設定を含めて確認する場合は、対象リポジトリ内で実行

⚠️ 注意

設定一覧にはメールアドレス、業務用パス、接続先などが含まれるため、記事への掲載前に機密情報・個人情報の有無を確認

出典：Git公式：First-Time Git Setup

リポジトリの初期化とステージング

Git Bashのホームフォルダから開始し、練習用のprojectを作成してREADME.mdをステージングする手順

1. 作業フォルダの作成・移動

ホームフォルダに練習用フォルダを作成

Git Bash
mkdir project

作成したフォルダへ移動

Git Bash
cd project

2. リポジトリの初期化

現在のフォルダをGitリポジトリとして初期化

Git Bash / PowerShell
git init

履歴や設定を管理する.gitフォルダを作成（初期設定により初期ブランチ名はmain）

実行結果

ユーザー名は公開用の例示値に置き換え

実行結果（例）

隠しフォルダを含む一覧を表示し、.gitの作成を確認

3. README.mdの作成

Helloを記載したREADME.mdを作成（同名ファイルがある場合は上書き）

Git Bash
echo "Hello" > README.md

4. README.mdのステージング

README.mdを次のコミットに含める対象として登録

Git Bash / PowerShell
git add README.md
実行結果
実行時の警告
warning: in the working copy of 'README.md', LF will be replaced by CRLF the next time Git touches it

作業ファイルの改行コード変換に関する警告であり、今回のステージングは成功（次のgit statusで確認）

5. ステージング状態の確認

コミット対象として登録されたファイルを確認

Git Bash / PowerShell
git status
実行結果
実行結果
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   README.md
  • On branch main：現在の作業対象（カレントブランチ）はmain
  • No commits yet：最初のコミットをまだ作成しておらず、変更履歴が未記録の状態
  • Changes to be committed：次のコミットに含める変更がステージングエリアへ登録済みの状態
  • new file: README.md：README.mdが新規ファイルとしてステージングされ、次のコミットへの追加対象
  • git rm --cached <file>...：この初回コミット前の状態でステージングを取り消すための案内（作業フォルダ内のファイルは保持）

ここまででREADME.mdのステージングが完了し、コミットによる履歴の保存は未実施

最初のコミット

1. コミットメッセージの入力

ステージング済みの変更を記録するため、練習用のprojectフォルダで実行

Git Bash / PowerShell
git commit

core.editorにcode --waitを設定済みの場合、VS Codeでコミットメッセージの編集画面を起動

  1. 開いたCOMMIT_EDITMSGの先頭に、コミットメッセージとしてinitial commitを入力
  2. Ctrl + Sで保存後、COMMIT_EDITMSGの編集タブを閉じる操作
  3. Git BashまたはPowerShellへ戻り、コミットの完了結果を確認

--waitの指定により、保存だけでなく編集タブを閉じるまでGitは待機（VS Code全体の終了は不要）

メッセージは#を付けずに入力（既定では#で始まる行は説明用コメントとして除外）

2. コミット結果の確認

実行結果
実行結果

  • main：コミットを作成したブランチ名
  • root-commit：親コミットを持たない最初のコミット

  • create mode 100644 README.md：README.mdを通常の非実行ファイルとして新規登録した記録

ここまででローカルリポジトリへの履歴保存が完了（GitHubへの送信は未実施）

よく使うコマンドとファイル

1. git init：リポジトリの初期化

指定したフォルダにGitの管理情報を作成し、バージョン管理を開始するためのコマンド

方法A：既存のフォルダを初期化

Git管理したいprojectフォルダへ移動し、初期化

Git Bash / PowerShell
cd project
git init

project/.gitを作成し、既存のファイルはそのまま保持。ファイルのステージングとコミットは別途必要

方法B：フォルダの作成と初期化を同時に実行

projectを作成したい親フォルダで実行

Git Bash / PowerShell
git init project
cd project

projectが存在しない場合はフォルダごと作成し、その中に.gitを作成。git init projectだけでは作業フォルダの移動は行われないため、続けてcd projectを実行

2つの方法は選択肢であり、両方の実行は不要。今回の練習用projectは初期化済みのため、再実行も不要

作成されるフォルダの構成

フォルダ構成
project/
├─ README.md    ← 編集するファイル（存在する場合）
└─ .git/        ← Gitの管理情報と履歴

通常はプロジェクトの最上位で初期化し、配下の各フォルダでのgit initは不要

2. git add：変更内容のステージング

作業ファイルの現在の内容を、次のコミットに含める内容として登録

Git Bash / PowerShell
git add README.md

主な用途は次の3つ

  • 新規ファイル：未追跡のファイルをステージングし、Gitの追跡対象へ追加
  • 追跡中のファイル：編集した内容をステージングへ反映
  • コンフリクトの解消後：修正した内容を登録し、解消済みとして扱うための操作

いずれも基本は「次のコミットに保存する内容の準備」

git addが登録するのは、実行した時点の内容。その後にREADME.mdを編集した場合、追加の編集内容も含めるには再度git addが必要

3. git commit：変更履歴の保存

ステージングエリアに準備した内容を、コミットとしてローカルリポジトリの履歴へ記録

エディタでメッセージを入力

Git Bash / PowerShell
git commit

今回の設定ではVS Codeが起動。コミットメッセージを入力し、保存後にCOMMIT_EDITMSGのタブを閉じてコミット完了

コマンドでメッセージを指定

Git Bash / PowerShell
git commit -m "Updates README.md"

-mはコミットメッセージの指定。エディタを開かずに履歴を記録

補足：追跡中の変更を自動でステージング

Git Bash / PowerShell
git commit -am "Updates README.md"

-aは追跡中のファイルの変更・削除を自動でステージングする指定、-mはメッセージの指定

未追跡の新規ファイルは-aの対象外のため、事前にgit addが必要。学習中は登録対象を把握しやすいよう、git addとgit commitを分けて実行

4. git config：設定の確認・変更

Gitの動作やユーザー情報、コマンドの別名などを設定するためのコマンド

よく使うコマンドに別名を設定

git log --graph --onelineを、git gとして登録

Git Bash / PowerShell
git config --global alias.g "log --graph --oneline"

登録した別名で実行（--graphは履歴のつながりを図示、--onelineは各コミットを1行で表示）

Git Bash / PowerShell
git g

状態確認のコマンドを短縮

git status -sを、git stとして登録

Git Bash / PowerShell
git config --global alias.st "status -s"

登録した別名で実行（表示対象の変更や未追跡ファイルがなければ出力なし）

Git Bash / PowerShell
git st

登録した設定を確認

Git Bash / PowerShell
git config --global alias.g
git config --global alias.st

--globalは現在のユーザーに共通する設定。別のリポジトリでも利用可能で、ターミナルの再起動後も再設定不要

入力を誤った設定の削除

今回誤って登録したarias.gを削除

Git Bash / PowerShell
git config --global --unset arias.g

正しい設定名はalias.g。arias.gは設定として保存されても、コマンドの別名としては認識されない状態

5. .gitignore：Gitの管理対象から除外

未追跡ファイルのうち、Gitで管理しないファイルやフォルダのパターンを指定するファイル。今回はproject内のtest.datを除外

.gitignoreの作成

test.datを除外対象として記載した.gitignoreを作成（既存の.gitignoreがある場合は上書きせず追記）

Git Bash
echo "test.dat" > .gitignore

.gitignoreは自動作成されないため、作成前のgit add .gitignoreは対象ファイルが見つからずエラー

除外状態の確認

Git Bash / PowerShell
git status -s

.gitignoreのみが未追跡ファイルとして表示され、test.datは一覧から除外。ファイル自体は作業フォルダに保持

除外ルールの保存

.gitignore自体はGitの管理対象として登録し、除外ルールをコミット

Git Bash / PowerShell
git add .gitignore
git status
git commit -m "adds .gitignore"

git statusでnew file: .gitignoreを確認後、コミットを実行

保存後の確認

Git Bash / PowerShell
git status -s

ほかに変更がなければ出力なし。隠しファイルの.gitignoreを含む一覧の確認には、Git Bashでls -laを使用

既にGitで追跡中のファイルは、.gitignoreに記載するだけでは除外されない点に注意

誤って登録したファイルを管理対象から除外する手順

一括登録はgit add -A（大文字のA）。誤って登録した場合は、次のいずれかの方法でファイルを残したまま管理対象から除外

新規ファイルをaddしただけの場合：既存のコミットがあるリポジトリでは、次の操作でステージングを取り消し

Git Bash / PowerShell
git restore --staged test.dat

リポジトリに最初のコミットがまだない場合は、上記の代わりに次を実行

Git Bash / PowerShell
git rm --cached test.dat

取り消し後、既存の.gitignoreを編集してtest.datを追記し、除外ルールを保存。以後、通常のgit add -Aでは登録対象外

既にコミット済みの場合：.gitignoreにtest.datを追記して保存後、次を実行

Git Bash / PowerShell
git rm --cached test.dat
git add .gitignore
git status
git commit -m "Stop tracking test.dat"

--cachedは作業ファイルを残してGitの管理対象から外す指定。git statusのdeleted: test.datは次のコミットから除外する予定であり、PC上のファイル削除ではない状態

上記は今回の対象ファイルだけを変更する手順。コミット前にgit statusで、ほかのステージング済み変更が含まれていないか確認

過去のコミットにはファイルが残る点に注意。秘密情報を登録した場合は、認証情報の失効・再発行や履歴からの削除など、別途対応が必要

ブランチとコンフリクト解消の演習

自己紹介ファイルの同じ行を、mainではTerraform、作業ブランチではDockerへ更新した履歴を統合する演習。実行ログを基に、入力ミスと不要な空行を除いて記載

対象は非公開の演習用リポジトリhsmts2/profile-merge-practice。cloneにはアクセス権とGitHub認証が必要（一般公開のサンプルではないため、第三者が実施する場合は同じ分岐状態の自分用リポジトリを準備）

開始場所はGit Bashの~/github-book。既存のprojectやfirstではなく、別フォルダへ履歴ごと複製
