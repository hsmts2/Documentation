AWS Managed Microsoft ADのユーザー・グループ管理

仕様

構成・動作

AWS Directory Service Dataは、AWS Managed Microsoft ADのユーザー、グループおよびグループメンバーシップを管理する機能です。「ユーザーとグループの管理」を有効化すると、AWSマネジメントコンソールから対応する操作を実施できます。

操作 動作・運用上の扱い
管理機能の有効化 対象ディレクトリで行う初期設定です。有効になっている場合は、作業のたびに有効化し直す必要はありません。
ユーザーの作成 ログイン名、初期パスワード、氏名などを設定してユーザーアカウントを作成します。作成時に既存グループへ追加できます。
グループへの追加 ユーザーは追加先グループに割り当てられた役割・権限を継承します。
グループからの削除 指定したグループのメンバーシップを削除します。ユーザーアカウント自体は残ります。
ユーザーアカウントの削除 ユーザーアカウント自体を削除します。グループメンバーシップの削除とは操作対象が異なります。

AWS Managed Microsoft ADのユーザーとグループの管理

管理範囲

管理方法の使い分け

管理方法 使用する作業
AWS Directory Service Dataコンソール 本手順の管理機能の有効化、ユーザーの作成・削除、既存グループへのメンバー追加・削除に使用します。
管理用EC2のAD管理ツール Directory Service Dataが対応していない操作や属性の管理に使用します。ADUC（Active Directoryユーザーとコンピューター）、ADAC（Active Directory管理センター）またはPowerShellで操作します。パスワードポリシーの設定はADACで実施します。

Amazon EC2インスタンスによるユーザーとグループの管理

ℹ️ 情報：IAM権限とActive Directoryの権限の違い

Directory Service Dataコンソールの操作には、作業者のIAM権限を使用します。ドメイン参加済みの管理用EC2からAD管理ツールを使用する場合は、Active Directory内で作業に必要な権限を持つユーザーとしてサインインします。IAMのAdministratorAccessだけで、AD管理ツール上の管理権限が付与されるわけではありません。

ユーザーとグループの管理方法

アカウントと委任グループの役割

管理対象 役割・運用上の扱い
Admin お客様用OUとAWSから委任された範囲を管理するアカウントです。Domain AdminsおよびEnterprise Adminsのメンバーではありません。日常運用では、作業者を識別できる管理ユーザーを使用します。
Administrator AWSが排他的に管理する組み込みの高権限アカウントです。お客様の作業では使用・変更しません。
AWS Reserved OU内のAWS_で始まるアカウント AWSが使用するサービス管理アカウントです。お客様の作業では変更しません。
krbtgt Kerberosで使用するアカウントです。お客様のユーザー管理作業では変更しません。
AWS Delegated Groups OU 用途別のAWS Delegated ...グループを格納するOUです。
AWS Delegated Administrators お客様用OUなどに対して強い委任管理権限を持つグループです。一般ユーザーには付与しません。
AWS Delegated FSx Administrators FSx管理用の高権限グループです。FSx管理を担当するユーザーを追加します。

管理者アカウントとグループのアクセス許可／AWS Managed Microsoft ADで作成される内容

既存のグループの入れ子関係は、ユーザーの追加・削除とは別に管理します。図10・12に表示される既存の子グループAWS Delegated Administratorsや、図14・15のAWSAdministratorsは変更しません。環境固有のグループは、所有者と用途を確認してから変更します。

制約事項

  • 管理機能の有効化とDirectory Service Dataによるユーザー・グループ管理は、対象ディレクトリのプライマリリージョンで実施します。
  • 本手順で使用するDirectory Service Dataコンソールでは、作成後のユーザーログイン名を変更できません。

パスワードポリシーの既定値

AWS Managed Microsoft ADのDefault Domain Policyには、次の値が設定されます。PSO（きめ細かなパスワードポリシー）が割り当てられていないユーザーには、このドメイン既定ポリシーが適用されます。

項目 AWS既定値
パスワード履歴 24個
最長有効期間 42日（Adminを含む）
最短有効期間 1日
最小長 7文字
複雑さ 有効
可逆暗号化による保存 無効

AWS Managed Microsoft ADのパスワードポリシー

⚠️ 注意：Adminパスワードの最長有効期間は既定で42日

Adminもパスワードの有効期間の対象です。運用開始前に、パスワードの保管担当者、変更担当者および次回変更日を決定します。

AWSが作成したDefault Domain Policyは、編集、削除または既存リンクの解除を行えません。異なるパスワードポリシーが必要な場合は、ADACのSystem\Password Settings Containerに用意されているCustomerPSO-01～CustomerPSO-05を設定し、ユーザーまたはセキュリティグループへ割り当てます。

AWSが作成するGPOと変更の制約

PSO 変更できない優先順位値
CustomerPSO-01 10
CustomerPSO-02 20
CustomerPSO-03 30
CustomerPSO-04 40
CustomerPSO-05 50

ユーザーへ直接割り当てたPSOは、グループ経由のPSOより優先されます。同じ適用区分で複数のPSOが該当する場合は、優先順位値が小さいPSOが優先されます。運用では、管理対象に応じたセキュリティグループ単位での割り当てを基本とします。

管理者によるパスワードのリセットでは、パスワード履歴と最短有効期間は適用されません。最小長や複雑さなどの品質要件は、パスワードの変更・リセット時に評価されます。

パスワードポリシーの適用方法と優先順位

ℹ️ 情報：パスワードリセット後のアカウント状態

Adminなどのパスワードは後から取得できません。Directory Serviceのパスワードリセットでは、対象アカウントが無効の場合も有効化されるため、実施後にアカウント状態を確認します。

構築作業

1. ユーザーとグループの管理機能を有効化する

  1. AWSマネジメントコンソールへサインインし、プライマリリージョンのアジアパシフィック（東京）を選択します。
  2. Directory Serviceの「ディレクトリ」を開きます。
  3. ディレクトリID、DNS名p-pm.example.com、ディレクトリタイプ「Microsoft AD」およびステータス「アクティブ」を照合します。
  4. 対象ディレクトリIDのリンクを選択し、詳細画面を開きます。
  1. 「ユーザー」タブを選択します。
  2. 「ユーザーとグループの管理」が「無効」になっている場合は、「有効にする」を選択します。既に「有効」の場合は、手順8へ進みます。
  1. 確認ダイアログの説明と対象ディレクトリを確認し、「有効にする」を選択します。
  1. 「ユーザーとグループの管理」が「有効」に変わり、「ユーザー」タブに一覧と「ユーザーを作成」が表示されることを確認します。

⚠️ 注意：管理機能を無効化する前に利用状況を確認する

誤って有効化した場合は、Directory Service Dataを使用する運用や自動処理がないことを確認してから、同じ詳細画面で無効化します。

Directory Service Dataコンソールによるユーザーの作成

  1. 対象ディレクトリの「ユーザー」タブで「ユーザーを作成」を選択します。
  2. ユーザーログイン名にsampleadminを入力します。
  3. 初期パスワードを入力し、確認用の欄へ同じパスワードを再入力します。
  4. 名、姓、表示名およびメールアドレスを、上表に従って入力します。その他の任意項目は、作業依頼に指定がある場合だけ入力します。
  5. パスワードが伏字になっていることを確認し、「次へ」を選択します。

⚠️ 注意：AWS Delegated Administratorsは管理担当者だけに付与する

AWS Delegated Administratorsは、強い委任管理権限を持つグループです。本手順では管理ユーザーsampleadminを追加します。一般ユーザーを作成する場合は、このグループを選択せず、業務に必要なグループだけを指定します。

  1. 「ユーザーをグループに追加」で、AWS Delegated Administratorsを選択します。作成時にグループを指定しない運用の場合は、グループを選択せずに進みます。
  2. 選択したグループを確認し、「次へ」を選択します。
  1. 確認画面で、ログイン名、名、姓、表示名、メールアドレスおよび所属予定グループを設定表と照合します。
  2. 内容に問題がなければ、「ユーザーを作成」を選択します。
  1. 作成成功メッセージと、ユーザー一覧にsampleadminが表示され、ステータスが「有効」になっていることを確認します。

一覧への反映が遅れている場合は、画面を更新して待機します。表示結果を確認するまで、同じ作成操作を繰り返しません。

3. ユーザーをグループから削除する

項目 設定値
削除元グループ AWS Delegated Administrators
グループから削除するユーザー sampleadmin

ℹ️ 情報：グループから削除してもユーザーアカウントは残る

この操作で削除する対象は、指定グループのメンバーシップです。ユーザーアカウント自体や、他のグループへの所属は残ります。

  1. 対象ディレクトリの「グループ」タブで、AWS Delegated Administratorsを開きます。
  2. 「メンバー」タブで、ログイン名がsampleadmin、メンバータイプが「ユーザー」の行を確認します。
  3. sampleadminだけを選択し、削除元グループ名とユーザーログイン名を再確認します。

⚠️ 注意：削除を選択する前にグループとユーザーを再確認する

本手順の掲載画面では、「削除」を選択した後に確認ダイアログは表示されず、メンバーシップの削除が実行されます。対象グループがAWS Delegated Administrators、対象ユーザーがsampleadminと一致していることを確認してから操作します。

  1. 対象に誤りがなければ、「削除」を選択します。
  2. 削除成功メッセージを確認し、メンバー一覧からsampleadminが消え、その他のユーザーや子グループが残っていることを確認します。
  1. 「ユーザー」タブでsampleadminを検索し、ユーザーアカウント自体が残っていることを確認します。

誤って削除した場合は作業依頼を確認し、削除元のグループへ対象ユーザーを再追加します。前の手順の操作方法を参照し、グループ名とユーザー名は実際に誤削除した対象へ置き換えます。グループから継承した権限の変更は、関連サービスでの再サインイン後に確認が必要になる場合があります。

4. ユーザーアカウントを削除する

項目 設定値
削除するユーザー samplework
表示名 sample work

削除前に、ログイン名、表示名、氏名、アカウントの状態および最終利用状況を作業依頼と照合します。WorkSpaces、FSx、共有フォルダー、バッチやサービスアカウントなどで使用されていないことを確認し、削除対象ユーザーのSIDと全グループメンバーシップを記録して保管します。

⚠️ 注意：ユーザーアカウントの削除はアクセス権にも影響する

この操作は、ユーザーアカウント自体を削除します。削除前の無効化期間やデータ引継ぎなど、必要な対応が完了していることを確認します。同じログイン名で新規作成してもSIDが変わるため、以前のアクセス権は自動では復旧しません。

セキュリティ識別子（SID）

  1. 対象ディレクトリの「ユーザー」タブを開きます。
  2. sampleworkを検索し、削除対象ユーザーだけを選択します。
  1. 「アクション」から「ユーザーアカウントを削除」を選択します。
  1. 確認ダイアログのユーザーログイン名sampleworkと表示名sample workを照合します。
  2. 対象ユーザーの情報と、アクセスに必要な情報が削除される旨を確認します。
  3. 対象に誤りがなければ、「ユーザーアカウントを削除」を選択します。
  1. 削除成功メッセージを確認します。
  2. 「ユーザー」タブでsampleworkを検索し、一覧に表示されず、対象外のユーザーが残っていることを確認します。

一覧への反映が遅れている場合は、画面を更新して待機します。状態を確認するまで、削除操作を繰り返しません。

❌ エラー：誤ったユーザーを削除した場合

追加の変更を停止し、対象ユーザーと影響範囲を確認します。復旧手順が整備されている場合は、ドメイン参加済みの管理用端末からActive Directory Recycle Binによる復元を検討します。ディレクトリのスナップショット復元はディレクトリ全体へ影響するため、単一ユーザーの通常復旧として実施しません。

削除済みオブジェクトの保持／スナップショットによるディレクトリの復元

5. パスワードポリシーを設定する（必要時）

この操作は、ドメイン既定のパスワードポリシーとは異なる設定が必要な場合に実施します。掲載画像のユーザー作成・グループ操作に必須の作業ではありません。

  1. ドメイン参加済みの管理用EC2へ、必要なAD管理権限を持つユーザーでサインインします。
  2. AD管理ツールが未導入の場合は、管理者権限のPowerShellで次のコマンドを実行します。
PowerShell
Install-WindowsFeature RSAT-ADDS

Active Directory管理ツールのインストール

DNS管理も行う場合は、サーバーマネージャーでDNS Server Toolsを追加します。

  1. 操作ユーザーがAWS Delegated Fine Grained Password Policy Administratorsのメンバーになっていることを確認します。
  2. ADACを起動してツリービューへ切り替え、System\Password Settings Containerを開きます。
  3. 使用するCustomerPSO-01～CustomerPSO-05を開きます。
  4. 承認されたパスワード履歴、長さ、有効期間、複雑さおよびロックアウト値を設定します。優先順位値は変更できません。
  5. 「直接の適用先」へ対象ユーザーまたはセキュリティグループを追加し、変更を保存します。
  6. レプリケーション後、「作業後確認」の手順で対象ユーザーの実効ポリシーを確認します。

パスワードポリシーの割り当てと確認／パスワードポリシー管理権限の委任

作業後確認

ユーザーとグループの状態を確認する

作業依頼で指定された操作の結果を確認します。本手順の掲載例を順に実施した場合は、次の最終状態を確認します。

  1. ディレクトリの詳細で、「ユーザーとグループの管理」が「有効」になっていることを確認します。
  2. 「ユーザー」タブでsampleadminが「有効」と表示されることを確認します。
  3. AWS Delegated FSx Administratorsのメンバーに、Adminとsampleadminが表示されることを確認します。
  4. AWS Delegated Administratorsのメンバーにsampleadminが表示されず、既存の対象外メンバーが残っていることを確認します。
  5. 「ユーザー」タブでsampleworkを検索し、一覧に表示されないことを確認します。

パスワードポリシーの適用結果を確認する（変更時のみ）

  1. 管理用EC2のPowerShellで、対象ユーザーの実効PSOを確認します。<ユーザー名>は確認対象のログイン名へ置き換えます。
PowerShell
Get-ADUserResultantPasswordPolicy -Identity '<ユーザー名>'
  1. 想定したCustomerPSO-0xと設定値が返されることを確認します。
  2. PSOを割り当てていないユーザーについてドメイン既定値を確認する場合は、次のコマンドを使用します。
PowerShell
Get-ADDefaultDomainPasswordPolicy -Identity 'p-pm.example.com'

Get-ADUserResultantPasswordPolicyは、Default Domain Policy自体の内容を表示するコマンドではありません。実効ポリシーの確認にnet userは使用しません。
