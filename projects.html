3. 個別案件

3.1 申請システムの基盤リプレイス

背景・目的
Amazon Linux 2のサポート終了に伴い、申請システムのLinux基盤をAmazon Linux 2023へリプレイス。顧客との要件確認から新環境の構築、切り替え、旧環境の撤去まで担当
設計・構築
お客様へのヒアリングを通じて既存構成と要件を整理し、ネットワーク・アクセス制御、OS・DBユーザーを設定。検証・本番環境の差分を反映して接続検証を実施し、パラメータシート、設定書、構成図、構築エビデンスを作成
監視・運用設定
CloudWatch Agent・Zabbixによる監視とログ収集を設定し、新環境の運用に必要な監視設定を整備
導入後の対応
DNS切り替えによる新環境への移行を実施。移行後に旧環境を撤去
技術環境
AWS：VPC、EC2、ALB、RDS、NAT Gateway、Route 53、S3、SNSOS：Amazon Linux 2023、Windows Server 2022監視：CloudWatch Agent、Zabbix

3.2 業務Webシステムの新規基盤構築

背景・目的
業務Webシステムの本番・検証基盤を新規構築。環境分離と本番環境の冗長化に加え、監視・監査、ログ保管、バックアップまで整備
設計・構築
本番・検証を別VPCに分離し、各環境のネットワーク、ALB、Web・DB基盤を構築。本番Webサーバーは2つのAZに分散配置し、本番RDSはMulti-AZ構成で冗長化
監視・運用設定
CloudWatchによる監視とCloudTrailによるAPI操作記録を設定。ELBアクセスログはS3、VPC Flow LogsはCloudWatch Logsへ保存し、AWS BackupでEC2・RDSのバックアップを設定
導入後の対応
納品後のメール配信運用を支援。SESの配信・バウンス・苦情通知とVDMを設定し、配信状況を確認。カスタムMAIL FROMと関連DNSレコードを設定し、テストメールで変更結果を確認
技術環境
AWS：VPC、EC2、ALB、RDS、Route 53、ACM、SES、CloudWatch、CloudWatch Logs、CloudTrail、S3、AWS BackupOS・DB：Red Hat Enterprise Linux 9、Amazon RDS for MySQL

4. 専任案件

特定のお客様の案件を2年2か月にわたり継続して担当し、先任エンジニアと私の2名が主担当として、AWS基盤の構築・運用を支援してきました。お客様の要件と既存環境を確認したうえで、構築・設定変更から試験、運用改善まで対応しています。

定例会では構成案や検証結果、作業の進捗を説明し、お客様と認識を合わせながら対応を進めました。また、設定書・構成図・運用資料を整備し、継続的な運用と引き継ぎに必要な情報をまとめています。

4.1 マルチVPC・閉域VDI基盤の構築

背景・目的
VDI・認証・ファイル共有を支えるAWS基盤を、6 VPCにまたがる構成で構築。構築後もセキュリティ機能の追加、設定変更、技術的な問い合わせ対応を継続して担当
設計・構築
VPC PeeringによるVPC間接続と、Direct Connect・VGWを利用した閉域接続の経路を設定。WorkSpaces、AWS Managed Microsoft AD、AD ConnectorによるVDI・認証基盤と、FSx for Windows File Serverによるファイル共有基盤を構築し、疎通・認証・共有接続を検証
監視・運用設定
Systems Managerによるパッチ管理とMaintenance Windowsの実行スケジュールを設定。構築後にNetwork Firewallを追加し、ルート変更・通信ルールの管理を担当。Security Hub・GuardDutyの検出結果を調査し、お客様への説明と対応を実施
導入後の対応
ADの操作・ポリシーやVDI運用に関する問い合わせに対応し、設定・更新方法と対処手順を案内。環境変更に合わせて設定書・構成図・パラメータシートを更新して定期的に提出し、運用手順書の整備と引き継ぎも担当
技術環境
ネットワーク：Amazon VPC、VPC Peering、Direct Connect、VGWVDI・認証・共有：WorkSpaces、AWS Managed Microsoft AD、AD Connector、FSx for Windows File Server運用・セキュリティ：Systems Manager（Patch Manager、Maintenance Windows）、Network Firewall、Security Hub、GuardDuty

4.2 WorkSpacesの運用コスト最適化

Amazon WorkSpacesには、時間課金（月額の基本料金＋利用時間分の料金）と月額固定の2つの料金体系があり、利用状況に合った課金モードを選ぶ必要があります。

お客様から、以前のEC2による運用と比べて料金が高くなったことに加え、約50台の利用状況を把握し、毎月1台ずつ課金モードを見直すことが難しいとのご相談をいただきました。

そこで、利用時間と設定した閾値に応じて課金モードを自動で切り替える「Cost Optimizer for Amazon WorkSpaces」を検討しました。私が仕様と動作条件を確認し、検証環境で課金モードの判定・切り替えやレポート出力を確認したうえで、お客様環境への導入を支援しました。

出典：Cost Optimizer for Amazon WorkSpaces（AWS公式）
出典：WorkSpacesの課金に関するFAQ（AWS公式）

導入支援に加え、自動停止までの時間を短縮し、利用状況に合わせたコンピューティングタイプの変更も支援しました。また、当時の料金条件に基づいて課金切替閾値の見直し案を作成しました。

CloudWatchダッシュボードで動作と課金モードを確認し、料金推移をお客様へ報告しました。これらの取り組み後、月額利用料金は2025年12月から2026年2月にかけて6,840.33 USD（59.9％）減少しました。

WorkSpacesの月額利用料金の推移
項目2025年12月2026年1月2026年2月
WorkSpaces台数49台49台50台
月額利用料金（USD）11,417.728,976.104,577.39
前月比比較基準21.4％減49.0％減

月額実績の比較であり、台数・利用時間・月の日数などの条件は同一ではありません。Cost Optimizerに加え、コンピューティングタイプと自動停止時間の見直しを含む複数施策後の推移です。

4.4 設計構築案件のドキュメント作成

お客様がエンドユーザー向けにVDI環境を構築するための技術支援を担当。セキュリティ・商流上の制約により、エンドユーザー環境の構築は弊社ではなくお客様が実施する体制でした。

弊社で事前に環境を構築し、要件への適合性、構築手順、改善点を確認。その結果を踏まえ、お客様が環境を構築できるよう、2026年8～9月にご依頼に基づく仕様書・構築手順書など計18件のドキュメントを作成しました。
