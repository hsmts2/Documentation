マルチVPC・閉域VDI基盤案件

全体構築・運用順序

認証基盤からVDIの利用開始、継続運用までを、依存関係と確認ポイントで整理します。各工程の詳細は個別ページに分け、このページを全体の道筋として使用します。

ネットワーク・認証基盤を整える

VPC間の接続とDNS通信を確認してから、Managed Microsoft ADを配置します。管理用EC2からディレクトリを操作できる状態を作り、AD Connector用のアカウントと権限委任を設定します。

WorkSpacesを展開する

ディレクトリ登録後にWorkSpaces用OUとGPOを整え、バンドルを指定して利用者へ割り当てます。カスタムイメージの作成・他アカウント共有は、基本構成の確認後に進めます。

04

WorkSpaces・OU・GPO

ターゲットOUと専用GPOのリンクを確認し、WorkSpaceを作成。

確認：意図したOUへのコンピューター配置、GPOの適用
05

カスタムイメージ・バンドル

Image Checkerで検査し、イメージとバンドルを作成・共有。

確認：共有先アカウントでの利用可否

パッチ・コスト・監視を運用に載せる

VDIの利用開始後も、パッチ適用、課金モード判定、監視通知を独立した運用として管理します。変更作業では実行結果と通知到達を確認し、次回の判断に使える記録を残します。

06

Systems Manager Patch Manager

対象タグ、ベースライン、メンテナンスウィンドウを設定。

確認：実行履歴、成功・失敗と対象インスタンス
07

WorkSpaces Cost Optimizer

ハブアカウントの構成、Dry Run、実行時刻とレポートを確認。

確認：判定結果、S3レポート、課金モード変更の条件
08

CloudWatch・SNS

EC2とWorkSpacesのメトリクス、アラーム、通知先を設定。

確認：SNS購読、アラーム遷移、メール受信
構成図の読み方

全体図は複数VPCの役割分担を示す構成例です。OU・GPO図はディレクトリ設定、Cost Optimizer図は単一ハブアカウント、監視図はメトリクスから通知までの流れをそれぞれ示します。別の検証環境の設定値を同一のデプロイ構成として扱わないでください。
